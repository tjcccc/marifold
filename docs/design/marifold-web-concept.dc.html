Marifold — Web concept
An agent-first AI workspace that feels like a native Apple system app in the browser. One conversation thread; two visually distinct reply kinds — plain answers, and runs where the agent visibly works with tools and asks permission. Calm, minimal, system-level.
TYPE
SF Pro Text / Display · 13px base · SF Mono for paths & commands
LIGHT
DARK
MATERIALS
Vibrancy on sidebar & toolbar, hairline dividers, soft shadow only on the approval sheet. One marigold accent — used for selection, the running state, and primary actions only.
Navigation: one segmented control in the toolbar switches Agent · Apps · Config. Left pane (profiles) and middle pane (sessions / apps / config sections) persist; only the right panel changes meaning. 1a Agent light · 1b Agent dark & edge states · 1c Apps · 1d Config · 1e Mobile.
Production-shell update (July 2026). These canvases remain the original visual exploration. The implemented Web UI is desktop-only and now uses one macOS-style primary sidebar: Profiles pushes into Sessions, system controls stay pinned at the bottom, and Agent · Apps sits in the contextual right-pane toolbar. Config is opened from Settings rather than presented as a peer workspace tab.

Screen: Agent (default landing). iMessage-like thread. User messages are gray bubbles; plain answers are open markdown text — no card chrome. A run is a quiet indented block: status line with elapsed time + Cancel, a small plan checklist, and one-line tool rows in SF Mono that update in place. It reads like an activity log inside the conversation, never dominating it.
Approval & steering. The approval sheet is the trust surface: what, where, how big — then Allow once (default, ⌘⏎), Always allow this kind, Deny. A soft marigold halo is the only attention cue. The input bar stays live during runs; sent guidance shows as a centered “Guidance applied” marker when picked up.
