# marifold v0.96.0 — workspaces across your devices, with a bridge you deploy in one command

Released 2026-10-25 · tag `v0.96.0` · [GitHub release](https://github.com/tjcccc/marifold/releases/tag/v0.96.0)

This is the first GitHub release since the 0.60.0 testflight. Its headline is device-hosted workspaces: your devices share one device's profiles, sessions and models through a small bridge you run yourself, which as of 0.96.0 deploys in one command on Cloudflare's free plan.

```sh
npm install -g marifold@0.96.0
```

Node.js 24 LTS is required.

## Workspaces and your own bridge

A workspace lets your other devices use one device's profiles, sessions and models. The devices talk through a bridge you host, which only relays end-to-end encrypted messages. It never sees your content or credentials.

- **One-command Cloudflare deploy.** `marifold workspace bridge deploy cloudflare` signs in to Cloudflare in the browser, uploads the bridge with a newly generated registration token, and prints its URL. No server to run, and personal use fits the free plan. On the same device, `marifold workspace create Home` and the Web UI's host form pick up that URL and token by themselves.
- **No database server.** The bridge keeps its state in SQLite: in a Durable Object on Cloudflare, or in a file next to a Node process. Messages that arrive within five seconds are never written to storage; one full test run (pairing, a 1 MB transfer, a reconnect, a revocation and a re-pair) wrote 9 rows in total.
- **A proxy for each device.** Each device can reach the bridge directly or through its own HTTP(S) proxy: `--proxy` on `workspace create` and `add`, `marifold workspace proxy <workspace> <url|direct>`, or the proxy field in the Web UI. The proxy is stored only on that device and covers registration, pairing and the connection itself. TLS to the bridge runs inside the proxy tunnel.
- **Or your own Linux server.** `marifold workspace bridge install` sets up the bridge with Docker Compose on any Linux VM (Aliyun ECS, AWS EC2, …), with SQLite on a Docker volume and optional Caddy HTTPS.

See [HOSTING.md](https://github.com/tjcccc/marifold/blob/v0.96.0/apps/bridge/HOSTING.md) for every way to host the bridge.

## Upgrading from npm 0.70–0.95

Workspaces shipped in 0.70.0 with a bridge that kept its state in Redis, with an optional Vercel deployment. 0.96.0 replaces Redis with SQLite and drops Vercel, so an existing setup needs a few steps:

- **Every paired device needs 0.96.0.** Devices in a workspace must run exactly the same version.
- **Workspaces don't move to a new bridge by themselves.** Deploy the new bridge, then on the host run `marifold workspace remove <workspace>` and `marifold workspace create <name>`. Profiles and sessions stay on the host; only the connection is replaced. On each guest, run `marifold workspace remove <workspace>`, then `marifold workspace add <url>` with a new invitation.
- **Older Linux installs need a fresh install.** Installs from 0.95 and earlier use Redis, and the updater refuses them. Remove the old install and run `marifold workspace bridge install` again (see "Removing an installation" in HOSTING.md).

## Also since 0.60.0

- **More in workspaces:** run tools on a chosen device (`@device`) and approve sudo on the device that asked for it. You can also pair a device that only runs tools (`invite --executor-only`), and share skills and marifold settings with approval.
- **The agent computer:** a Linux container that gives the agent its own computer, with a separate account per profile and network access only through a proxy.
- **A full-screen terminal UI:** session picker, `--resume`, takeover of sessions running elsewhere, and `/btw` side questions.
- **Models:** one global **Deep** switch for more model effort, a one-line `model = "provider/model"` setting per profile, ChatGPT and xAI sign-in through a proxy, and experimental built-in web search with source citations.
- **Agent and SkillApps:** memory during agent runs, folder approvals that last for one run, an interactive SkillApp builder, `copy_file`, and profile rename that keeps your sessions.

The full history is in [DEVLOG.md](https://github.com/tjcccc/marifold/blob/v0.96.0/DEVLOG.md).
