# Flow: add or route a provider / model

1. Add a registry entry in `packages/core/src/config/ProviderRegistry.ts` (name, label, kind, type, default base URL, API key env, known models). Use type `openai-compatible` unless it is Ollama or Anthropic; `ProviderFactory.create` (`packages/core/src/config/ProviderFactory.ts`) builds the adapter by type.
2. For OAuth providers, add the sign-in prompt in `packages/cli/src/input/ModelPicker.ts` with a helper in `packages/cli/src/auth/`, a token refresh module in `packages/core/src/config/` (compare `ChatGptTokenRefresh.ts`, `XaiTokenRefresh.ts`, `GitHubCopilotAuth.ts`), and a branch in `ProviderEngines.refreshCredentials` (`packages/core/src/runtime/ProviderEngines.ts`), which persists rotated tokens through `withOAuthCredentials` (`packages/core/src/config/OAuthCredentials.ts`).
3. Endpoint routing for OpenAI-compatible providers is `MarifoldOpenAICompatProvider.endpointForRequest` (`packages/core/src/config/MarifoldOpenAICompatProvider.ts`): ChatGPT, Copilot models in `GITHUB_COPILOT_RESPONSES_MODELS`, and hosted-search requests use the Responses API; the rest use Chat Completions. Subscription headers live in the same file.
4. Hosted web search support is `ProviderFactory.nativeWebSearchStrategy` (per-provider `native_web_search` override); reasoning/think support is `ProviderEngines.priestConfig`/`supportsThink`.
5. `marifold model add <provider> <model>` persists to `[models].options` (`packages/cli/src/commands/model.ts`, `ConfigManager.addModel`); validation and model listing via `packages/core/src/config/ProviderInspector.ts`. The Web config screens use `packages/service/src/ConfigRoutes.ts`.
6. Tests: `packages/core/tests/MarifoldOpenAICompatProvider.test.ts`, `packages/core/tests/OAuthCredentials.test.ts`, `packages/core/tests/ProviderInspector.test.ts`, `packages/core/tests/NativeWebSearch.test.ts`.
